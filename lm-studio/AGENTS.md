# Agent Instructions for lm-studio-rpm

This repository converts LM Studio Debian packages to RPM format for Fedora/RHEL/CentOS/SUSE systems.

## Project Structure

| File | Purpose |
|------|---------|
| `gen_spec.py` | Python script that extracts metadata from `.deb` packages and generates RPM spec files |
| `lm-studio.spec` | RPM spec file (auto-generated by `gen_spec.py`) |
| `Makefile` | Build automation with phony targets |
| `*.deb` / `*.rpm` | Package files (input/output) |

## Build Commands

### Using Make (Recommended)

```bash
make all              # Generate spec and build RPM using mock (full pipeline)
make mock             # Build RPM using mock (from existing spec)
make spec             # Generate spec file from deb package
make rpm              # Build RPM using rpmbuild (local, for testing)
make test             # Test metadata extraction (./gen_spec.py output to stdout)
make sources          # Download/verify sources for spec
make clean            # Remove build artifacts (*.rpm, rpms/, lm-studio-buildroot/)
make install-deps     # Install required build dependencies
make help             # Display available targets and variables
```

### Mock Build Pipeline

The spec file uses the deb package as Source0. The `%prep` section extracts it using `ar` and `tar`:

```bash
# Step 1: Generate spec with Source0 pointing to deb
make spec

# Step 2: Download/verify sources (copies Source0 to SOURCES/)
make sources

# Step 3: Build SRPM and RPM with mock
make mock
```

### Direct Commands

```bash
# Generate spec file
./gen_spec.py "LM-Studio-VERSION-x64.deb" -o lm-studio.spec

# Extract metadata for testing (output to stdout)
./gen_spec.py "LM-Studio-VERSION-x64.deb" -o /dev/stdout

# Build RPM manually with mock
spectool -g -S ./*.spec
mock --buildsrpm --sources=./ --spec ./*.spec --resultdir=./rpms/
mock --rebuild ./rpms/*.src.rpm --resultdir=./rpms/

# Build RPM manually with rpmbuild (local)
mkdir -p buildroot && dpkg-deb -x package.deb buildroot
rpmbuild --buildroot="$(pwd)/buildroot" -bb --target x86_64 lm-studio.spec
```

## Code Style

### Python (gen_spec.py)

| Aspect | Convention |
|--------|------------|
| **Shebang** | `#!/usr/bin/env python3` |
| **Python version** | Python 3 only |
| **Type hints** | Required for function parameters and return types |
| **Line length** | 100 characters maximum |
| **Indentation** | 4 spaces (no tabs) |
| **String quotes** | Double quotes `"` for strings; single quotes `'` only when nested |

**Import order** (alphabetical within each group):
1. Standard library modules (`argparse`, `os`, `re`, `subprocess`, etc.)
2. Third-party modules (none in this project)
3. Local modules (none in this project)

**Naming conventions**:
- Functions: `snake_case` (e.g., `extract_deb_control`)
- Classes: `PascalCase` (not used in this project)
- Constants: `SCREAMING_SNAKE_CASE` (e.g., `DEFAULT_SPEC_NAME`)
- Variables: `snake_case` (e.g., `deb_path`, `control_data`)

**Error handling patterns**:
```python
# Fatal errors - print to stderr and exit
print(f"Error message: {result.stderr}", file=sys.stderr)
sys.exit(1)

# Subprocess calls with error checking
result = subprocess.run(["command", "arg"], capture_output=True, text=True)
if result.returncode != 0:
    print(f"Error: {result.stderr}", file=sys.stderr)
    sys.exit(1)

# Optional operations (should not fail build)
command || true
```

### Shell Scripts (%post, %preun sections)

| Aspect | Convention |
|--------|------------|
| **Shebang** | `#!/usr/bin/env bash` |
| **Variables** | Use `${var}` syntax, always double-quote expansions |
| **Conditionals** | Prefer `test` over `[ ]` for clarity |
| **Error handling** | Use `|| true` for optional commands |
| **Checks** | Use `command -v foo >/dev/null 2>&1` to check command existence |

**Example patterns**:
```bash
# Variable expansion with quoting
rm -rf "${BUILD_ROOT}"

# Existence checks
if test -d "${BUILD_ROOT}/usr/share/icons/hicolor/0x0"; then
    mv "${BUILD_ROOT}/usr/share/icons/hicolor/0x0" \
       "${BUILD_ROOT}/usr/share/icons/hicolor/1024x1024"
fi

# Optional commands (should not fail)
chmod 4755 '/opt/LM-Studio/chrome-sandbox' || true
```

### RPM Spec Files

**Section order**:
```
Name → Version → Release → Summary → License → Vendor → URL → 
BuildArch → %description → %post → %postun → %files → %changelog
```

**Macro usage**: Use RPM macros for portability:
- `%{NAME}`, `%{VERSION}`, `%{RELEASE}`, `%{ARCH}`
- `%{_rpmdir}`, `%{_rpmfilename}`, `%{_unpackaged_files_terminate_build}`

**Comments**: Use `##` prefix for extracted metadata markers from dpkg-deb.

**%postun section**: Handles package removal - removes the `/usr/bin/lm-studio` symlink via `update-alternatives` or direct removal. This script runs when the RPM is uninstalled.

**Example postrm script from deb**:
```bash
#!/bin/bash

# Delete the link to the binary
if type update-alternatives >/dev/null 2>&1; then
    update-alternatives --remove 'lm-studio' '/usr/bin/lm-studio'
else
    rm -f '/usr/bin/lm-studio'
fi
```

## Workflow

1. Download a new LM Studio `.deb` package from https://lmstudio.ai/download
2. Run `make test` to verify metadata extraction works
3. Run `make spec` to regenerate the spec file
4. Review `lm-studio.spec` for correctness
5. Run `make all` to build the RPM package using mock
6. Test the RPM in a container/VM: `rpm -ivh rpms/lm-studio-*.x86_64.rpm`
7. Verify installation: `rpm -qi lm-studio`

Do not hardcode desktop/icon paths in the spec — `generate_spec()` derives them from
`list_deb_data_paths()` so upstream layout changes do not break the build.

### Bundled `lms` CLI

`%install` creates a relative symlink `/usr/bin/lms` -> `../../opt/LM-Studio/resources/app/.webpack/lms`
and owns it in `%files`. It is only generated when `LMS_CLI_PATH` exists in the deb, so an
upstream layout change cannot break the build. Verify with `lms --version` (prints
`CLI commit: <sha>`).

### In-app updater removed

The deb ships `opt/LM-Studio/resources/app-update.yml` (electron-builder updater config:
`provider: s3`, bucket `lmstudio-updaters`) plus `resources/package-type` (`deb`).
`%install` deletes `app-update.yml` (`UPDATER_CONFIG_PATH`) so the RPM-installed app cannot
offer in-app updates. Why this matters:

- The updater escalates via sudo/pkexec — `main/index.js` carries
  `'Running as non-root user, using sudo to install: '` + `SCRIPT_DATA` and `pkexec` /
  `gksudo` / `kdesudo` helpers — so it writes into the root-owned `/opt/LM-Studio`.
- It renames the outgoing files instead of removing them, leaving
  `"<file>;<hex unix ts>"` rollback copies. On a live host one update pass at
  `0x69ffad4d` = 2026-05-10 00:55:25 left 91 files / 684 MB behind, 73 of them
  byte-identical to the new version (Electron runtime assets that do not change between
  releases). `rpm -U` does not clean them because no package owns them.
- `resources/package-type` is left as-is; it is inert once the config is gone.

If a future build surfaces an "update check failed" toast, the config delete is too blunt —
patch the `checkForUpdates` call site in `main/index.js` instead.

### Hardlink dedup

`find_duplicate_groups()` uses the deb's own `md5sums` manifest (no re-hashing) to find
byte-identical files at different paths and emits `ln -f "$BR<src>" "$BR<dup>"` into
`%install`; RPM stores one copy and reinstalls them as hardlinks. Only files >=
`MIN_HARDLINK_BYTES` (16 KiB) qualify. In 0.4.25 that is 11 groups / 24.1 MB, mostly the
llama.cpp libs duplicated between the `avx2` and `vulkan` backend dirs. Verify after a build:

```bash
rpm2cpio ~/rpmbuild/RPMS/x86_64/lm-studio-*.rpm | cpio -idm --quiet
stat -c '%i %h %n' \
  opt/LM-Studio/resources/app/.webpack/bin/extensions/backends/llama.cpp-linux-x86_64-avx2-2.41.0/libllama.so \
  opt/LM-Studio/resources/app/.webpack/bin/extensions/backends/llama.cpp-linux-x86_64-vulkan-avx2-2.41.0/libllama.so
# both lines must show the same inode with links=2
```

## Troubleshooting

### Common Issues

**No deb files found**: Ensure you're in the correct directory and a `.deb` file exists:
```bash
ls -la LM-Studio-*.deb
```

**RPM build fails with unpackaged files**: The `_unpackaged_files_terminate_build` macro is set to 0 to allow this, but verify `%files` section lists all needed paths.

**Icon directory issue**: `%prep` still renames the legacy `0x0` icon directory to `1024x1024`
when present (pre-0.4.25 debs). Since 0.4.25 the deb ships a proper hicolor set
(16x16 … 512x512) and the desktop file is `ai.elementlabs.lmstudio.desktop`, not
`lm-studio.desktop`; both are picked up automatically by `build_files_entries()`.

**`<file>;69ffad4d` copies are not package files**: LM Studio's own runtime updater renames
the previous version's files with a `;<hex>` suffix and leaves them under `/opt/LM-Studio`.
They show up in `sha1sum` output and eat disk (on a live 0.4.25 install 73 of them,
391 MB, were byte-identical to their base file) but they are absent from the deb, so the
spec cannot hardlink them. Dedupe them on the host, not in the package.

**Permission denied**: Ensure write permissions to the output directory.
