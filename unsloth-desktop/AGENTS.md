# Agent Instructions for unsloth-desktop-rpm

This repository converts the Unsloth Desktop Debian package to RPM format
for Fedora/RHEL/CentOS/SUSE systems. It's a sibling project to
`lm-studio-rpm`, same tooling shape, but `gen_spec.py` is layout-driven
rather than hardcoding paths for one specific package — see
"Why this project doesn't hardcode paths" below, it's the main thing to
understand before touching `gen_spec.py`.

## Project Structure

| File | Purpose |
|------|---------|
| `gen_spec.py` | Python script that extracts metadata from `.deb` packages and generates RPM spec files |
| `unsloth.spec` | RPM spec file (auto-generated by `gen_spec.py`, gitignored) |
| `Makefile` | Build automation with phony targets |
| `*.deb` / `*.rpm` | Package files (input/output, gitignored) |

## Build Commands

### Using Make (Recommended)

```bash
make all              # Download deb, generate spec, and build RPM using mock
make mock             # Build RPM using mock (from existing spec)
make spec             # Generate spec file from deb package
make rpm              # Build RPM using rpmbuild (local, for testing)
make test             # Test metadata extraction (./gen_spec.py output to stdout)
make sources          # Download/verify sources for spec
make clean            # Remove build artifacts (*.rpm, rpms/, unsloth-buildroot/)
make install-deps     # Install required build dependencies
make help             # Display available targets and variables
```

### Mock Build Pipeline

The spec file uses the deb package as Source0. The `%prep` section extracts it using `ar` and `tar`:

```bash
# Step 1: Generate spec with Source0 pointing to deb
make spec

# Step 2: Download/verify sources (copies Source0 to SOURCES/)
make sources

# Step 3: Build SRPM and RPM with mock
make mock
```

### Direct Commands

```bash
# Generate spec file
./gen_spec.py "Unsloth-Desktop-VERSION-Ubuntu.deb" -o unsloth.spec

# Extract metadata for testing (output to stdout)
./gen_spec.py "Unsloth-Desktop-VERSION-Ubuntu.deb" -o /dev/stdout

# Build RPM manually with mock
spectool -g -S ./*.spec
mock --buildsrpm --sources=./ --spec ./*.spec --resultdir=./rpms/
mock --rebuild ./rpms/*.src.rpm --resultdir=./rpms/

# Build RPM manually with rpmbuild (local)
rpmbuild -bb --target x86_64 --define "_sourcedir $(pwd)" unsloth.spec
```

## Why this project doesn't hardcode paths

The LM Studio template this was cloned from assumes an Electron app under
`/opt/<App>` whose desktop file and icon are named exactly `%{name}.desktop`
/ `%{name}.png`. Unsloth Desktop breaks every one of those assumptions
(everything lives under `/usr`, the desktop file is `Unsloth.desktop`, the
icon is `unsloth-studio.png`, package name is `unsloth`), so `gen_spec.py`
derives things from the deb's actual contents instead:

- `extract_deb_contents()` (`gen_spec.py:85`) parses `dpkg-deb --contents`
  into `(kind, path)` pairs.
- `toplevel_dirs()` (`gen_spec.py:113`) drives the `%install` `cp -a`
  lines — only directories that actually exist in the deb (e.g. `usr`, and
  `opt` only if present) get copied.
- `owned_paths()` (`gen_spec.py:121`), together with `STANDARD_DIRS` /
  `HICOLOR_DIR_RE` (`gen_spec.py:24`/`38`), builds `%files`: every shipped
  file/symlink, plus any directory not already owned by `filesystem` or
  `hicolor-icon-theme` (verify ownership assumptions with
  `rpm -qf <path>` before adding a new standard dir to that set).
- `extract_deb_license()` (`gen_spec.py:137`) looks for an
  `SPDX-License-Identifier` line in maintainer scripts first, then in the
  raw data archive bytes, before falling back to a `/usr/share/doc/<pkg>`
  reference (only if that path actually exists in the deb).
- `build_requires()` (`gen_spec.py:162`) maps the deb's `Depends:` (Debian
  package names) to Fedora package names via `DEB_TO_RPM_DEPS`
  (`gen_spec.py:16`). Unmapped deps are emitted as a `## unmapped debian
  dep: X` comment rather than guessed — check `rpm -q <candidate>` on a
  Fedora box before adding a mapping.

When adapting this project for a *different* package in the future, expect
to mainly touch `DEB_TO_RPM_DEPS` and `STANDARD_DIRS`; the rest should
already be generic enough to handle a different file layout.

## Code Style

### Python (gen_spec.py)

| Aspect | Convention |
|--------|------------|
| **Shebang** | `#!/usr/bin/env python3` |
| **Python version** | Python 3 only |
| **Type hints** | Required for function parameters and return types |
| **Line length** | 100 characters maximum |
| **Indentation** | 4 spaces (no tabs) |
| **String quotes** | Double quotes `"` for strings; single quotes `'` only when nested |

**Import order** (alphabetical within each group):
1. Standard library modules (`argparse`, `os`, `re`, `subprocess`, etc.)
2. Third-party modules (none in this project)
3. Local modules (none in this project)

**Naming conventions**:
- Functions: `snake_case` (e.g., `extract_deb_control`)
- Classes: `PascalCase` (not used in this project)
- Constants: `SCREAMING_SNAKE_CASE` (e.g., `DEFAULT_SPEC_NAME`, `DEB_TO_RPM_DEPS`)
- Variables: `snake_case` (e.g., `deb_path`, `control_data`)

**Error handling patterns**:
```python
# Fatal errors - print to stderr and exit
print(f"Error message: {result.stderr}", file=sys.stderr)
sys.exit(1)

# Subprocess calls with error checking
result = subprocess.run(["command", "arg"], capture_output=True, text=True)
if result.returncode != 0:
    print(f"Error: {result.stderr}", file=sys.stderr)
    sys.exit(1)

# Optional operations (should not fail build)
command || true
```

### Shell Scripts (%post, %postun sections)

| Aspect | Convention |
|--------|------------|
| **Shebang** | `#!/usr/bin/env bash` |
| **Variables** | Use `${var}` syntax, always double-quote expansions |
| **Conditionals** | Prefer `test` over `[ ]` for clarity |
| **Error handling** | Use `|| true` for optional commands |
| **Checks** | Use `command -v foo >/dev/null 2>&1` or `hash foo 2>/dev/null` to check command existence |

**Example patterns**:
```bash
# Existence checks
if hash update-desktop-database 2>/dev/null; then
    update-desktop-database /usr/share/applications || true
fi
```

### RPM Spec Files

**Section order**:
```
Name → Version → Release → Summary → License → Vendor → URL →
BuildArch → Requires → Provides/Conflicts/Obsoletes → %description →
%install → %post → %postun → %files → %changelog
```

**Macro usage**: Use RPM macros for portability:
- `%{NAME}`, `%{VERSION}`, `%{RELEASE}`, `%{ARCH}`
- `%{_rpmdir}`, `%{_rpmfilename}`, `%{_unpackaged_files_terminate_build}`

**Comments**: Use `##` prefix for extracted metadata markers, including
unmapped Debian dependencies that need a human to pick a Fedora package
name.

**%postun section**: Unsloth's deb ships no meaningful `postrm` (it's a
no-op), so the generated `%postun` just best-effort refreshes the desktop
database. If a future release adds a real `postrm`, `gen_spec.py` will use
it verbatim instead (see `extract_deb_scripts`).

### Runtime Dependencies (Requires:)

`DEB_TO_RPM_DEPS` (`gen_spec.py:16`) currently maps:

| Debian package | Fedora package | Why |
|----------------|-----------------|-----|
| `libwebkit2gtk-4.1-0` | `webkit2gtk4.1` | Linked directly (see `ldd usr/bin/unsloth-studio`) |
| `libgtk-3-0` | `gtk3` | Linked directly |
| `libappindicator3-1` | `libappindicator-gtk3` | `dlopen()`'d for the tray icon, not linked — rpmbuild's automatic dependency scan won't catch this one, so the explicit `Requires:` is load-bearing |

Verified against Fedora 44 (`rpm -q webkit2gtk4.1 gtk3 libappindicator-gtk3`
all resolve). Re-verify before targeting a different Fedora release.

## Workflow

1. Download a new Unsloth Desktop `.deb` from
   https://github.com/unslothai/unsloth/releases (or `make download`)
2. Run `make test` to verify metadata extraction works
3. Run `make spec` to regenerate the spec file
4. Review `unsloth.spec` for correctness — especially the `%files` list and
   any new `## unmapped debian dep:` lines
5. Run `make all` to build the RPM package using mock
6. Test the RPM in a container/VM: `rpm -ivh rpms/unsloth-*.x86_64.rpm`
7. Verify installation: `rpm -qi unsloth` and launch `unsloth-studio`

## Troubleshooting

### Common Issues

**No deb files found**: Ensure you're in the correct directory and a `.deb` file exists:
```bash
ls -la Unsloth-Desktop-*-Ubuntu.deb
```

**RPM build fails with unpackaged files**: The `_unpackaged_files_terminate_build` macro is set to 0 to allow this, but verify `%files` section (built by `owned_paths()`) lists all needed paths — run `make test` and diff against `dpkg-deb --contents`.

**File listed twice**: means a directory owned in `%files` overlaps with a
separately-listed file inside it, or a new standard dir needs adding to
`STANDARD_DIRS`/`HICOLOR_DIR_RE`. Check with `rpm -qf <path>` whether
another package already owns the parent directory.

**Permission denied**: Ensure write permissions to the output directory.

### Debug Commands

```bash
# Inspect deb package contents
dpkg-deb --contents Unsloth-Desktop-*-Ubuntu.deb

# View deb control information
dpkg-deb --info Unsloth-Desktop-*-Ubuntu.deb

# Check what package owns a path on the build host
rpm -qf /usr/share/icons/hicolor/32x32/apps

# Check generated spec
cat unsloth.spec
```
